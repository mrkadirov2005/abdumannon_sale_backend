Қарздорлар: new debt for an archived person

What happens on the Қарздорлар page (and in Moliya) when a debt is created with the name of someone who is already in the Архив, plus the related name-matching risks.

Based on the code in src/pages/debt/DebtsPage.tsx and src/pages/Finance/useFinanceLogic.ts and the shop database as of 12 Oct 2026. Nothing in the app or database was changed to produce this document.

1. How a person's balance is calculated

The app does not store a balance per person. Every time the page loads it groups all debts and payments by name and recalculates:

Олган (took) = sum of all the person's debts Берган (gave) = debts marked "returned" + Moliya payments whose description starts with "Name: ..." Қолдиқ (left) = Олган − Берган, shown as 0 if negative Ортиқча (over) = Берган − Олган, when they paid more than they owed Қолдиқ > 0 → person is in Қарздорлар (active) Қолдиқ = 0 → person is in Архив (closed)
Key point: names are compared ignoring capital letters and spaces at the start and end. So a new debt for Шухрат ака is added to the same person as an old debt for шухрат ака , together with all of that person's old payments. The name field in the "new debt" form also suggests existing names, including archived ones, so this happens often.

2. The cases at a glance

Case 1 works

Archived person had paid exactly. New debt → they move back to Қарздорлар with the full new amount owed.

Case 2a hidden

Archived person overpaid, new debt is smaller than the overpayment → debt is silently covered, person stays in Архив, nothing shows as owed.

Case 2b reduced

Archived person overpaid, new debt is bigger than the overpayment → they return to Қарздорлар but owe less than the new debt.

Case 3 split

Name typed differently (typo, double space) → a separate new person; old payments and overpayment are not linked.

3. Case 1: archived person paid exactly works

Example: the customer took 100,000 on credit and paid back 100,000, so they are in the Архив. A new debt of 30,000 is created with the same name.

MomentОлганБерганҚолдиқОртиқчаShown in
Before the new debt100,000100,0000—Архив
After a new debt of 30,000130,000100,00030,000—Қарздорлар
Result: correct. The person moves from Архив back to Қарздорлар automatically, owing exactly the new 30,000, and their old debts and payments stay in their history.

Side effect in Statistika: while the new debt is unpaid, the person's old debts are counted as "Қайтарилмаган" (not returned) again, because the person as a whole is no longer fully paid. The money totals are right; only the returned/unreturned counts jump.

4. Case 2: archived person overpaid

Example: the customer took 100,000 on credit and paid 150,000, so 50,000 is overpaid. They are in the Архив with Қолдиқ 0 (the list never shows negative balances).

Case 2a: new debt smaller than the overpayment hidden

MomentОлганБерганҚолдиқОртиқчаShown in
Before the new debt100,000150,000050,000Архив
After a new debt of 30,000130,000150,000020,000Архив
Problem: the new 30,000 debt is paid automatically out of the old 50,000 overpayment. The person stays in the Архив and the debt never appears in the Қарздорлар list. Anyone who does not know about the overpayment will think the debt disappeared.

Case 2b: new debt bigger than the overpayment reduced

MomentОлганБерганҚолдиқОртиқчаShown in
Before the new debt100,000150,000050,000Архив
After a new debt of 80,000180,000150,00030,000—Қарздорлар
Result: the person returns to Қарздорлар but owes only 30,000, not the 80,000 that was just given. The 50,000 overpayment was used up. This is correct if the overpayment really was a credit for the customer, but it is not visible anywhere when the debt is created.

5. Case 3: the name is typed differently split

Only capital letters and spaces at the start and end are ignored. Anything else makes a different person:

Old nameNew nameSame person in the lists?
Шухрат акашухрат акаYes
Шухрат ака Шухрат ака (spaces at the ends)Yes
Шухрат акаШухрат ака (double space inside)No
Шухрат акаШухрат ака прямойNo
Шухрат акаShuxrat aka (Latin letters)No
Result: the new debt starts a separate person. Their old payments and any overpayment are not linked, so the customer appears twice: once in the Архив with the old history (and any overpayment) and once in Қарздорлар with the full new debt.
Small inconsistency: the Statistika cards and Moliya also ignore double spaces inside the name, but the Қарздорлар/Архив lists do not. For Шухрат ака vs Шухрат ака the cards would count one person and the lists two, so the figures could differ slightly. The same rule applies to payments: a payment only counts if its description starts with the person's name followed by a colon (Шухрат ака: ...).

6. Does Moliya behave the same?

Yes. Moliya also groups debts and payments by name, so the same cases apply and the two pages stay consistent:

  • Case 1: the person reappears in Moliya → Қарздорлар with the new amount.
  • Case 2: an overpaid customer is shown in Moliya → Қарзларим as money you owe back. When a new debt uses up the overpayment, they disappear from Қарзларим (fully in 2a, and in 2b they move to Қарздорлар with the reduced amount).
  • Case 3: a differently typed name is a separate person in Moliya too.

8. Possible improvements

None of these are implemented. They are options to decide on:

  1. Warn when creating a debt for a customer with an overpayment, e.g. "This customer has 50,000 overpaid; the new debt will be covered by it." The user then decides whether that is correct.
  2. Show the credit in the lists: display "Қолдиқ: −50,000 (кредит)" instead of 0, so overpayments are always visible and the columns always add up (Олган − Берган = Қолдиқ).
  3. Match names the same way everywhere: ignore double spaces inside names in the lists too, so the lists, Statistika and Moliya always agree.
  4. Warn about near-duplicate names when creating a debt (e.g. "Шухрат ака" vs "Шухрат ака"), to avoid accidentally splitting one customer into two.
